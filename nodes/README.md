# Nodes

All ROS2 node source code lives here. Deployment is via Ansible: the repo is cloned on each target and uv venvs are synced (`uv sync --frozen --no-dev`) from these paths.

## Layout

- **ros2_master/** — ROS2 daemon (used by server and client).
- **master2master/** — Topic proxy (Client only).
- **d435_obstacle_cloud/** - Config-only `rtabmap_util point_cloud_xyz`: head_rgbd_cpp's edge-masked full-FOV D435 depth (`/head/d435/depth_filtered/image_raw` + `camera_info`) -> decimated `/head/d435/points` (PointCloud2, `d435_depth_optical_frame`); publishes only from real synced frames; replaced `tof_obstacle_cloud` (Client only). See `d435_obstacle_cloud/README.md`.
- **bridges/feetech_servos/** — Feetech servos bridge (configurable namespace, extra namespaces on the same bus, position or wheel/velocity mode per joint; leader/follower example configs).
  - Ansible node `base_servos` (the base bus) also carries the `head` group (`head_pan` ID 20, `head_tilt` ID 21): `/head/joint_states` and `/head/joint_commands`, speed/acceleration caps written with every goal, home pose in `startup_position_rad`.
- **head_state_publisher/** - robot_state_publisher on `web_ui/urdf/head.urdf`, driven by `/head/joint_states`: publishes the head TF (pan/tilt chain and the D435 `d435_*` frames, with the applied `head_chain.json` override; Client only). See `head_state_publisher/README.md`.
- **leader_bridge/** — Leader arm teleop relay: `/leader/joint_states` (server) to `/filter/input_joint_updates` (filter_node leader input); replaces master2master's leader rule, never bypasses filter_node arbitration (Client only).
- **lerobot_teleop/** — Leader → follower teleop node (Client only).
- **filter_node/** — Modular joint command filter (e.g. Kalman) for follower teleop (Client only).
- **test_joint_api/** — REST API for joint updates feeding the same path as master2master (Client only).
- **topic_scraper_api/** — Dynamic ROS topic scraper + HTTP JSON API for runtime diagnostics (Client + Server).
- **bridges/bno055_imu/** — BNO055 IMU bridge; publishes `sensor_msgs/Imu` on `/imu/data` with covariance for Nav2 (Client only).
- **bridges/gps_rtk/** — GPS RTK bridge for LC29H-BS (base, Server) and LC29H-DA (rover, Client); publishes `sensor_msgs/NavSatFix`, streams RTCM3 over TCP.
- **bridges/rplidar_a1/** — RPLidar A1 bridge; publishes `sensor_msgs/LaserScan` on `/scan` (Client only).
- **bridges/realsense_d435/** - Config of the head RealSense D435 (stock `realsense2_camera`, Ansible node `realsense_d435`): `/head/d435/*` colour, depth and depth aligned to colour at 640x360 @ 15 fps, no IMU, no TF (head.urdf owns the frames); the only head and arm camera (Client only). See `bridges/realsense_d435/README.md`.
- **head_camera_cpp/** - C++ (rclcpp + libcamera) node for the Camera Module 3 (IMX708). On the head it is retired (Ansible `head_camera_cpp` is `present: false`, the type only uninstalls the old unit; the head D435 colour replaced it). The same source runs the body-fixed CSI cameras: Ansible node types `front_camera` (cam0, `/front_camera/*`, metrics 19121) and `back_camera` (cam1, `/back_camera/*`, metrics 19122, disabled until fitted), 1152x648 at 15 fps, no zoom, background cgroup tier. See `head_camera_cpp/README.md`.
- **head_rgbd_cpp/** - C++ (rclcpp) head RGB-D adapter: the D435 aligned depth and colour (`/head/d435/*`) -> `/head_rgbd/*` (depth, JPEG RGB, coloured cloud) for RTAB-Map, ground guidance and marker_detector, and the edge-masked full-FOV depth `/head/d435/depth_filtered/*` for `d435_obstacle_cloud`. Prometheus on 19117, normal cgroup tier. See `head_rgbd_cpp/README.md`.
- **ground_estimator_cpp/** - C++ (rclcpp, PCL) node that fits the floor plane from the filtered head D435 cloud (`/head/d435/points_filtered`) with the IMU prior and publishes `/ground/*` (obstacle and drop points, state, warning areas) for the Nav2 local costmap, the mcp_server map summary and floor_guard; normal cgroup tier, metrics on 19119
- **head_aim_cpp/** - C++ (rclcpp) node that points the pan/tilt head (D435) along the Nav2 path ahead of the leading wheels while a NavigateToPose goal is active (`/head/joint_commands`, source tag `head_aim`), steps and settles, yields to `web_ui` / `autonomy` head commands and homes the head at goal end; normal cgroup tier
- **head_rgbd_calibration/** - Python service for the head D435 calibration (the D435 intrinsics check, the floor fit, head-from-arm and arm offsets) and the front/back CSI camera intrinsics (`/api/csi/{camera}/...`, Apply writes `applied/<name>_camera_calibration.yaml` and restarts that camera's unit), with the session store on the robot (`/var/lib/ros2/head_rgbd_calibration`), thumbnails, coverage and results with safe ids and atomic writes. See `head_rgbd_calibration/README.md`.
- **pi_cameras/** - Retired: the node and its directory are gone (the Ansible entry is `present: false`, deploying it uninstalls the unit and `camera_ros` is purged). Superseded by `head_camera_cpp/`, itself retired by the head D435; the old front and back camera topics no longer exist.
- **swerve_drive_controller/** — Swerve controller: cmd_vel → steer positions + wheel velocities (IK, +-90 deg steering), odometry from FK with slip-aware wheel dropping and residual-based covariance (Client only).
- **static_tf_publisher/** — Static TF base_link → sensor frames (Client only); every `frames:` entry needs all of x, y, z, roll, pitch, yaw (an incomplete one is skipped and logged), and the front/back camera frames appear only once `front_camera_mount` / `back_camera_mount` hold the user's tape measurement.
- **robot_localization_ekf/** — EKF fuses swerve `/odom` + lidar `/odom_rf2o_twist` + BNO055 `/imu/data` → `/odometry/filtered` and the odom → base_link TF (Client only).
- **rf2o_laser_odometry/** — rf2o lidar odometry (source-built from a pinned upstream commit) on `/scan_filtered` → `/odom_rf2o`; no TF (Client only).
- **rf2o_odom_relay/** — Re-publishes rf2o as a body-frame twist with a real covariance on `/odom_rf2o_twist` for the EKF (Client only).
- **map_guard/** - SLAM map protection: scores each scan against the map and detects the robot being lifted, carried or rotated by hand; pauses slam_toolbox while disturbed, then resumes or backs up and resets the map (web_ui drops its GPS anchor); notifies the agent on `/robot_events` only while it is busy. Starts in dry run (Client only).
- **map_guard_cpp/** - C++ (rclcpp) port of `map_guard`, side by side: same topics, services, config and metrics port (19110). Ansible node type `map_guard_cpp` is `present: false` until the cut-over; the Python `map_guard` stays installed as the rollback. Built on the Pi from the repo tree (Client only).
- **laser_filter/** — Python self filter removing lidar returns and head D435 cloud points on the robot body (polygon settable at runtime; mcp_server sets the dynamic footprint when the arm is released): `/scan` → `/scan_filtered` for SLAM, costmaps and collision monitor, `/head/d435/points` → `/head/d435/points_filtered` (Client only).
- **slam_toolbox/** — slam_toolbox online async SLAM from `/scan` + odometry TF: publishes `/map` and map → odom; saved posegraph in `/var/lib/ros2/maps` is reloaded at start (Client only).
- **nav2_bringup/** — Nav2 2D navigation stack with repo params: footprint-aware Smac lattice global planner (OMNI, H-shaped footprint) on the SLAM map, MPPI Omni controller for the swerve base (Client only).
- **haptic_controller/** — Force-feedback (resistance) and zero-G hold mode for leader gripper; gripper-only pilot (Client only).
- **steamdeck_ui/** — Touch-friendly Electron dashboard for SteamDeck (controller.ros2.lan). Camera preview, sensor/effector graphs, local nav map, GPS map, overlay bar. Python rclpy bridge subscribes to `/controller/*` topics and serves them via local WebSocket. Native app — no Docker.
- **web_ui/** — FastAPI + React + Three.js browser dashboard replacing steamdeck_ui. Serves config, URDF files, and topic data over HTTP/WebSocket; the Map tab shows the SLAM map, robot pose, global/local plans and sets Nav2 goals. Native app — no Docker.
- **mcp_server/** - Robot MCP server (Streamable HTTP on port 18200, bearer token): robot state, camera images, map summary, Nav2 navigation, drive, arm control via the filter_node autonomy lease, and /arm/home + /arm/set_home services, plus map frontiers (`list_frontiers`, `go_to_frontier`, numbered topdown layer; own numpy/scipy WFD); every camera image becomes a photo POI owned by poi_store (mcp_server writes the JPEG and sends the add; `list_lookups` / `get_lookup_image` / `annotate_lookup` / `delete_photos`) (Client only).
- **poi_store/** - Points/areas of interest on the map (name, note, status): JSON file store with latched `/poi/list`, `/poi/command` and `/poi/result` topics; also owns the camera photo index (photo POIs, latched `/poi/photos` summary, retention); edited by the agent (mcp_server) and the user (web_ui) (Client only).
- **rtabmap_mapping/** - Server launch/config-only node type: one component_container with `rgbd_sync` and the RTAB-Map core (RGB-D from the client uplink, odometry from slam_toolbox's `map -> base_link`, no own TF), database in `/var/lib/ros2/rtabmap`; 200% CPU cap, `memory_max` 900M. The stream contract is `config/map3d_topics.yaml` (Server only). See `rtabmap_mapping/README.md`.
- **map3d_manager_cpp/** - C++ (rclcpp) node on the server (Ansible node `map3d_manager`): JSON save/load/reset commands on `/map3d/command` to RTAB-Map's `Empty` services, database copy on save, reset follows `map_guard`, status and result topics (`/map3d/status`, `/map3d/result`); 20% / 128M (Server only). See `map3d_manager_cpp/README.md`.
- **map3d_uplink/** - Client launch-only node type: the one static-peer process (`ROS_STATIC_PEERS`) carrying the map3d streams, a component_container with lazy `topic_tools` throttle/relay and an `image_transport` compressedDepth republisher per entry of the contract; background tier (Client only). See `map3d_uplink/README.md`.
- **Head RGB-D mapping stream** - `head_rgbd_cpp` publishes 2 Hz exact-stamp D435 depth + JPEG RGB pairs on `/head_rgbd/*`; `map3d_uplink` ships those pairs to the server.
- **map_manager/** - Named maps: save, list, load and delete bundles of the slam_toolbox pose graph, occupancy grid, POI set and last robot pose under `/var/lib/ros2/maps/named`; a load deserializes with a pose hint, replaces the POIs in poi_store and verifies the scan against the map (`/map_manager/*` topics) (Client only).
- **costmap_zones/** - Nav2 keepout and speed zones from area POIs: rasterises the open areas whose `zone` is `keepout` or `slow` (poi_store `/poi/list`) onto exactly the `/map` grid and publishes latched masks (`/costmap_zones/keepout_mask`: -1 outside, slow value (`slow_zone_mask_value`, default 60, a non-lethal path cost) in slow zones, 100 in keep-outs; `/costmap_zones/speed_mask`: 0 outside, speed percent inside) plus the `nav2_msgs/CostmapFilterInfo` for the KeepoutFilter and SpeedFilter; slow-zone cost makes Nav2 prefer paths around slow areas (Client only).
- **marker_detector/** - Printed QR metadata markers: decodes them in every configured camera (`cameras:` the head D435 colour, front and back CSI; one pipeline per camera, a camera without camera_info is skipped), estimates the marker pose (IPPE, the marker plane from the aligned D435 depth `depth_plane` resolves the ambiguity; no zoom stills), publishes `/markers/detections` and upserts marker POIs in poi_store; metrics on port 19118 (Client only).
- **claude_agent/** - Claude (Agent SDK, Opus) chat agent: the user types instructions in the web UI, the agent answers and drives the robot through mcp_server's tools; HTTP/WebSocket API on 127.0.0.1:18300, effector calls capped per instruction, OAuth token deployed by Ansible, runs as its own non-root user; ships read-only skills (survey, sightseeing, planning and more), workflows (templates discovery, drive_to_target, pick_place) that seed the task plan, and a retrospectives store with a web feed (Client only).

Shared Python libraries used by multiple nodes live in [../shared/](../shared/). See [CLAUDE.md](../CLAUDE.md) for conventions (type hints, unit tests, rebuild on source change).
