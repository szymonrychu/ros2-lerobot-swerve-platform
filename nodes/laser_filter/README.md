# laser_filter

Removes RPLidar returns that hit the robot itself, so SLAM, the Nav2 costmaps and the collision monitor do not treat the robot body as an obstacle.

**Audience:** Mid-level Python dev with ROS2.

- **Node:** `laser_filters` `scan_to_scan_filter_chain` (apt `ros-jazzy-laser-filters`), launched by Ansible as `laser_filter` on the client.
- **Topics:** subscribes `/scan` (RPLidar, frame `laser_frame`), publishes `/scan_filtered`.
- **Filter:** `StaticLaserScanPolygonFilter` in `base_link` removing everything inside the robot's H-shaped top-view outline (side frames, crossbar, steering wheel envelopes, lidar column) plus a 1 cm margin: `config/footprint_filter.yaml`. Returns inside the front notch (between the front wheels, ahead of the crossbar) and the rear notch (between the rear wheels, behind the crossbar) are real obstacles and are kept; the old box filter (470 x 386 mm + 1 cm) removed them. Needs the static TF `base_link -> laser_frame`.
- **Polygon:** generated by `scripts/gen_nav_footprint.py` from the same body model as the Nav2 footprint and the collision monitor StopBox (see `nodes/nav2_bringup/README.md`, "Footprint"); do not edit it by hand. `polygon_padding` stays 0 because laser_filters pads by moving each vertex by `sign(x)`, `sign(y)`, which shrinks a non-convex outline at the notch walls; the margin is generated into the polygon instead. The filter's point-in-polygon test is a ray-crossing test, valid for non-convex polygons.
- **Static variant:** the lidar mount does not move, so `StaticLaserScanPolygonFilter` (laser_filters 2.0.10, Jazzy) transforms the polygon into `laser_frame` once (`transform_timeout` 5 s) and then only does a precomputed cos/sin lookup and the polygon test per beam, cheaper than the box filter's per-scan point cloud projection. Checked in Docker (2026-10-10): a return on the side frame was removed, returns in both notches were kept.
- **Why:** on the robot the lidar sees parts of the platform 0.22-0.24 m from the sensor. slam_toolbox's `min_laser_range` (0.15 m) does not remove them, so without the filter they become occupied cells around the robot and the planner can only plan to the robot's own position.

Consumers: `slam_toolbox` (`scan_topic`), Nav2 global/local costmap obstacle layers and `collision_monitor` (`nodes/nav2_bringup/config/nav2_params.yaml`).
