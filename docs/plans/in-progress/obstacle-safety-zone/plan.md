# Obstacle safety zone narrower and never trapping

Covers bug 1 ("Area around obstacles is too wide") and bug 2 ("Area around obstacles is stopping robot for no
reason") in one plan: both are the same guards (footprint, collision_monitor StopBox and CliffStop, local costmap
marking), generated by the same script and pinned by the same tests, so two plans would edit the same lines twice.

## What and why

What: shrink the effective safety zone around obstacles to near the real body, and remove every guard that freezes
the robot once it is close to an obstacle, so a new goal always moves it, including away from the obstacle.

Why, from the user: "It's ok if robot is millimeters from the obstacle. It's also ok to slightly bump the obstacles
sometimes. It's not ok to keep safety margin so minimal, that normally reachable paths for robot are software
locked from reaching." And: "once robot hits an obstacle it's already too late + it is correct to move away from it.
Tweak or disable this system."

Root causes found (discovery, config read; live logs not collected, robot unreachable):

- Bug 2, primary: collision_monitor StopBox `rotate` sub-polygon is a 0.35 m circle (circumscribed radius + 2 cm)
  selected for every command with linear speed under 5 mm/s, including zero twist and pure rotation
  (nodes/nav2_bringup/config/nav2_params.yaml:719-726, comment :690). Any 4 lidar or D435 points within 0.35 m of
  base_link stop every turn. RotationShim turns in place first when a new path is > 45 deg off (:66-75), so the new
  goal never starts; recoveries Spin is also a turn; the goal aborts after 20 s (progress checker :51-56).
- Bug 2, secondary: CliffStop `rotate` and `forward` sub-polygons are footprint + 0.25 m (cliff_margin_m,
  scripts/gen_nav_footprint.yaml:44); 4 below-floor D435 points inside them already stop every forward, sideways and
  rotation command (action approach, nav2_params.yaml:816-852). Also start-in-collision: footprint padding 0 against a
  2.5 cm grid makes Smac and MPPI reject a start whose outline touches one lethal cell.
- Bug 1: the cost halo (inflation 0.35 m, factor 24) is already minimal and mostly cosmetic. What locks paths is the
  outline: parked-arm overhang to x 0.3225, zero tolerance on a 2.5 cm grid, 5 cm D435 voxels and two STVL layers
  marking the same obstacle (obstacles grow 2.5-5 cm), the 0.25 m cliff margin, and the rotate circle blocking any
  heading change near a wall.

## Scope ladder

Rungs are cumulative: each rung includes everything above it.

### Rung 1: MVP - guards tweaked, both bugs fixed (recommended)

- 1.1: StopBox `rotate` sub-polygon becomes the footprint + stopbox_margin_m (2 cm), no longer the swept 0.35 m
  circle; directional sub-polygons stay (moving away from an obstacle already passes them).
- 1.2: CliffStop: cliff_margin_m 0.25 to 0.05; its `rotate` sub-polygon becomes the bare footprint, so a turn is
  stopped only by below-floor points under the body.
- 1.3: a `footprint_tolerance_m` generator option (default 0.02) shrinks the costmap footprint (Smac, MPPI,
  RotationShim, behaviour server) by 2 cm, so millimetre approaches and slight bumps are legal and a start touching
  one lethal cell is not "in collision"; the laser_filter self polygon stays unshrunk (self returns must still be
  removed); the mcp_server runtime formulas (footprint.py, footprint_geometry.py) apply the same tolerance.
- 1.4: inflation_radius and cost_scaling_factor recomputed from the new footprint by the same generator rule.
- 1.5: tests/test_nav_footprint.py, tests/test_nav_depth_collision.py, tests/test_mcp_server_config.py updated to pin
  the new shapes; nodes/nav2_bringup/README.md (Footprint, Penalty zone, StopBox, CliffStop) updated.
- 1.6: deploy nav2_bringup, laser_filter, mcp_server; live acceptance with topic_scraper on
  /collision_monitor_state plus the nav2 journal: (a) drive to within ~2 cm of a box, set a goal behind the robot,
  it turns and leaves; (b) a doorway / gap with a few cm real clearance is planned and driven.
- Tradeoff: real contact becomes possible (accepted by the user); a turn next to a wall may scrape a corner.
- Size: small. One generator, its YAML, generated files, three test files, one README; one deploy.

### Rung 2: less noise in the local costmap

- 2.1: depth STVL `mark_threshold` 0 to 1 and `voxel_decay` 15 to 5 s (both STVL layers), so single noisy D435
  points and stale marks stop growing obstacles.
- 2.2: ground_voxel_layer stops double-marking what depth_voxel_layer already marks (its obstacle band off; it keeps
  only below-floor/cliff marking).
- 2.3: tests/test_nav_depth_voxel_layer.py, tests/test_nav_ground_voxel_layer.py and README updated.
- Tradeoff: obstacles out of the head view are forgotten sooner; conflicts with the head-aims plan's optional memory
  rung, which goes the other way (longer decay). Size: small, config and tests only.

### Rung 3: explicit escape when started in collision

- 3.1: custom BT XML (copy of the Jazzy replanning tree) whose recovery runs ClearLocalCostmap then a short
  DriveOnHeading away from the nearest lethal cell before Spin, instead of BackUp-only.
- 3.2: StopBox action_type `approach` (time_before_collision) instead of `stop`, so any command moving away from
  points passes even with points inside the polygon edge. Tests pin both.
- Tradeoff: one BT file to maintain against Nav2 updates; approach mode trusts the simulated motion. Size: medium.

### Rung 4: complete - rotation guard that sweeps only the commanded turn, UI visibility

- 4.1: a C++ collision_monitor-side check (or patched overlay like the MPPI one) that, for an in-place turn, sweeps
  the footprint only through the commanded angle over the next ~0.5 s, replacing the static rotate sub-polygon.
- 4.2: web UI Map tab shows which guard is stopping the robot (/collision_monitor_state polygon and action) and a
  toggle to disable StopBox / CliffStop for the session.
- Tradeoff: new code in the safety path, needs on-robot validation runs. Size: large.

## Non-goals

- No change to the global costmap layers or to Smac's planning algorithm.
- No change to the source_timeout fail-safe (stale D435 or head TF stops everything; user decision 2026-10-18).
- No head aiming (separate plan "D435 head aims along the planned path").
- No inflation_radius below the circumscribed radius (Nav2 then checks the full footprint everywhere: more CPU, no
  less blocking).

## Design

Every geometry change goes through scripts/gen_nav_footprint.py and scripts/gen_nav_footprint.yaml; the generated
blocks between `# >>> gen_nav_footprint:` markers in nav2_params.yaml, laser_filter footprint_filter.yaml and the
mcp_server nav_footprint block in ansible/group_vars/client.yml are regenerated, never hand-edited
(tests/test_nav_footprint.py fails otherwise). Functions touched: `stopbox_polygons` (:340), `cliffstop_polygons`
(:379), plus a new tolerance option applied to the costmap footprint only.

## Decisions

- D1: one plan for both bugs (same guards, same generator, same tests). (my call)
- D2: tweak rather than disable: StopBox stays for directional motion (it is the only fast lidar stop), only its
  rotate circle shrinks. (my call)
