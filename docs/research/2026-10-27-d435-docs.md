## Synthesis

On Jazzy, 4.59.1 with librealsense 2.59.1 is current. The repo's launch arg names are all valid. The real issues are elsewhere. Depth at 90 fps with color at 30 fps gives up hardware sync (datasheet Table 4-6). Align and pointcloud run on the Pi's CPU, because every filter, align and pointcloud is a host-side librealsense block. Aligned depth is cropped to the narrower color FOV. The apt build appears to use the stock-kernel V4L2 backend. Intel's docs say this gets metadata on the stock kernel, but they say nothing about Raspberry Pi, and the only Pi 5 evidence is forum anecdote. Datasheet min-Z (195 mm at 848x480, 120 mm at 480x270) and +-2% accuracy within 2 m fit the head use case. For the gripper they favour a lower depth mode. Firmware should be 5.17.3.10 or later, flashed with rs-fw-update after stopping the node. On-chip calibration is a health check, to act on only above 0.25. Two repo-side defects are concrete: the udev rule matches only the D435i PID (0b3a), not D435 (0b07), and the node README documents pre-4.55 topic names.

## Plan inputs

- reuse: `ros-jazzy-realsense2-camera` 4.59.1 via `rs_launch.py` with launch args (camera_namespace/camera_name/base_frame_id, publish_tf, `*_filter.enable`, clip_distance); `extrinsics/depth_to_color` and per-stream camera_info; `device_info` service; datasheet min-Z table for mode choice; on-chip calibration health-check (Viewer or `auto_calibrated_device`).
- do-not-build: custom depth-to-color alignment, decimation, or pointcloud nodes (the driver blocks exist; or use depth_image_proc downstream); custom firmware tooling (use rs-fw-update); a source build of librealsense unless the apt V4L2 build fails on Pi 5 hardware.
- fix-as-ac: udev rules in `ansible/roles/ros2_base/tasks/main.yml` must cover PID 0b07 (plain D435), not only 0b3a; depth and color on the same fps (e.g. both 30 or 15) for HW sync; set `camera_name`/`camera_namespace` explicitly to avoid `camera_link` collision with static_tf_publisher, and provide the URDF parent -> `<camera_name>_link`; update `nodes/bridges/realsense_d435i/README.md` topic names (`/<ns>/<name>/...`) and drop `unite_imu_method:=linear_interpolation`; drop the redundant `enable_accel/enable_gyro` args; verify firmware >= 5.17.3.10 at bring-up; Pi 5 on a 5 V 5 A supply (1.6 A USB budget) and camera on a USB3 port, cable plugged into the camera first.
- ideas: low-CPU profile = depth 848x480x15 or 30 with `decimation_filter.enable:=true` (magnitude 2 -> 424x240) and `align_depth.enable:=false` (align only when RGB-D is consumed); 480x270 or 640x360 mode for gripper near range; `clip_distance:=2.0` for the head ground view; intra-process component container if a consumer runs on the Pi; one on-chip health-check at bring-up, recalibrate only if > 0.25.
